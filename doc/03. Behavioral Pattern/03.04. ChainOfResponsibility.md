# Chain Of Responsibility 패턴 정리

## 1. 패턴 개요

Chain Of Responsibility 패턴은 요청 처리 객체를 하나로 고정하지 않고, 연쇄(Chain)로 연결된 후보들이 순차적으로 요청을 처리하도록 만든다.  
요청자는 "누가 처리하는지"를 알 필요 없이 시작점만 호출한다.

## 2. Version 01 코드 리뷰

`Version 01`은 패턴의 기본 흐름을 학습하기에 적절하며, 연쇄 연결과 처리 위임이 명확하게 드러난다.

- 장점
- `SetNext()`를 이용한 체인 구성 방식이 직관적이다.
- `Limit / Special / Odd / NotSupport`로 책임 분리가 분명하다.

- 개선 필요점
- `SupportRequest()`가 `Console.WriteLine` 부수효과에 의존해 재사용성과 테스트 용이성이 낮다.
- 호출자가 처리 결과를 값으로 받지 못해 후속 로직 분기가 어렵다.
- `null` 입력에 대한 방어 로직이 없다.

## 3. Version 02 개선 내용

Version 02는 **구조 변경 1개**를 중심으로 개선했다.

- 구조 변경: `SupportRequest()`의 결과 객체 반환
- 기존: 출력 중심(`Console.WriteLine`)
- 변경: 값 중심(`ChainOfResponsibility_Result`)

### 3.1 핵심 변경 포인트

- `ChainOfResponsibility_Result` 추가
- `IsResolved`, `Resolver`, `Message`, `Trouble` 제공
- `SupportRequest()`가 `ChainOfResponsibility_Result`를 반환
- `SetNext(null)`, `SupportRequest(null)` 방어 추가
- `Trouble` 생성 시 음수 번호 방어 추가

### 3.2 기대 효과

- 콘솔 출력 여부와 무관하게 결과를 안정적으로 검증 가능
- 애플리케이션 레이어에서 처리 결과 기반 분기/로깅/집계 가능
- 경계 케이스에 대한 실패 원인 조기 노출

## 4. 시나리오 검증

다음 체인을 구성해 `0..499 (step 33)` 요청을 처리한다.

- Alice: `NotSupport`
- Bob: `LimitSupport(100)`
- Charlie: `SpecialSupport(429)`
- Diana: `LimitSupport(200)`
- Elmo: `OddSupport`
- Fred: `LimitSupport(300)`

검증 결과:
- 429는 `Charlie`가 처리
- 300 이상 짝수(예: 330, 396, 462)는 처리 실패
- 홀수(예: 231, 297, 363, 495)는 `Elmo`가 처리
