# Chain Of Responsibility 패턴 정리

## 1. 패턴 개요

Chain Of Responsibility 패턴은 요청 처리자를 하나로 고정하지 않고, 체인으로 연결된 여러 처리자가 순차적으로 요청을 처리하도록 만든다.  
요청자는 어떤 객체가 최종 처리했는지 알 필요 없이 시작 처리자만 호출한다.

## 2. Version 01 코드 리뷰

`Version 01`은 패턴의 기본 흐름(체인 연결, 순차 처리, 실패 전파)을 학습하기에 적합하다.

- 장점
- `SetNext()` 체이닝으로 연결 방식이 직관적이다.
- `Limit / Special / Odd / NotSupport`로 책임 분리가 명확하다.

- 개선 필요점
- `SupportRequest()`가 `Console.WriteLine` 중심이라 테스트 자동화와 재사용이 어렵다.
- 처리 결과를 값으로 반환하지 않아 후속 로직 분기가 제한된다.
- `null` 입력 방어가 없다.

## 3. Version 02 개선

Version 02는 출력 중심 구조를 결과 객체 반환 구조로 개선했다.

- `ChainOfResponsibility_Result` 도입 (`IsResolved`, `Resolver`, `Trouble`, `Message`)
- `SupportRequest()`가 `ChainOfResponsibility_Result` 반환
- `SetNext(null)`, `SupportRequest(null)`, 음수 Trouble 번호 방어

## 4. Version 03 개선 (Delegate 기반 처리자)

### 4.1 구조 변경 포인트

Version 03은 "처리 조건 정의 방식"을 상속에서 delegate 주입으로 전환했다.

- 변경 전: 처리자 클래스를 상속(`LimitSupport`, `OddSupport` 등)해 `Resolve()` 재정의
- 변경 후: `ChainOfResponsibility_DelegateSupport`에 `Func<Trouble, bool>` 주입
- 공통 생성은 `ChainOfResponsibility_SupportFactory`로 제공

### 4.2 기대 효과

- 작은 조건 변경 시 새 클래스를 늘리지 않고 람다로 빠르게 구성 가능
- 테스트에서 처리 흐름 추적(trace)과 케이스 조합이 쉬움
- 체인/결과 계약(`SupportRequest`, `ChainOfResponsibility_Result`)은 Ver2와 동일하게 유지

## 5. Scenario 테스트 기준

다음 체인과 입력 시퀀스를 기준으로 시나리오를 검증한다.

- 체인
- Alice: `NotSupport`
- Bob: `LimitSupport(100)`
- Charlie: `SpecialSupport(429)`
- Diana: `LimitSupport(200)`
- Elmo: `OddSupport`
- Fred: `LimitSupport(300)`

- 입력
- `0..499` 범위, `33` step 증가

- 검증 포인트
- `429`는 `Charlie`가 처리
- `330`, `396`, `462`는 미해결
- `231`, `297`, `363`, `495`는 `Elmo`가 처리
- 메시지 순서가 입력 순서와 정확히 일치

참고 기준: `easyspubjava/DesignPatternLAB`의 Chain Of Responsibility 실행 예제와 동등한 시나리오 흐름으로 검증한다.

## 6. 테스트 반영 내역

- Ver1: 기본 동작 + 시나리오 결과 검증
- Ver2: 결과 객체/예외 방어 + 시나리오 결과 검증
- Ver3: delegate 주입 동작 + 체인 조기 종료(흐름 순서) + 시나리오 결과 검증

## 8. C# 문법 설명
### 8.1 체인 연결과 추상 처리자
- 대상 코드: `ChainOfResponsibility_Support`, `SetNext`, `SupportRequest`
- 선언 의미: 처리자 공통 흐름(자기 처리 시도 -> 다음 전달)을 상위 추상 클래스에 고정한다.
- 실행 시 동작: 요청은 체인 순서대로 전달되며, 처리 성공 시 조기 종료된다.
- 주의점/오해하기 쉬운 차이: `SetNext(null)`을 허용하면 체인 구성이 깨져 런타임에서 예기치 않은 실패가 발생한다.

### 8.2 Delegate 기반 처리 조건 (`Func<Trouble, bool>`)
- 대상 코드: `ChainOfResponsibility_DelegateSupport`, `ChainOfResponsibility_SupportFactory`
- 선언 의미: 상속으로 클래스를 늘리지 않고, 람다/함수로 처리 조건을 주입한다.
- 실행 시 동작: 동일 처리자 타입으로 다양한 Resolve 조건을 동적으로 구성할 수 있다.
- 주의점/오해하기 쉬운 차이: delegate 캡처 값이 외부 상태에 의존하면 테스트 재현성이 낮아질 수 있다.
