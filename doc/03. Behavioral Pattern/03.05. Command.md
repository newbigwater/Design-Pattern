# Command 패턴 정리

## 1. 패턴 개요

Command 패턴은 요청 자체를 객체로 캡슐화해 호출자와 실행자를 분리한다.
이력 저장, 재실행(replay), 취소(undo) 같은 흐름 제어를 객체 단위로 구성할 수 있다.

## 2. Version 01 이식 내용

`Version 01`은 Java 학습 예제의 구조를 C#으로 옮기는 데 집중했다.

- `Command_Command`: 실행 인터페이스
- `Command_Drawable`: 그리기 인터페이스
- `Command_DrawCommand`: 좌표 드로우 요청
- `Command_MacroCommand`: 명령 집합 실행/추가/undo/clear
- `Command_DrawCanvas`: `Paint()` 시 이력 재실행
- `Command_Main`: `MouseDragged`, `ClickClearButton` 이벤트 흐름 재현

핵심 시나리오:
- 드래그 이벤트에서 `append` 후 즉시 `execute`
- clear 버튼 클릭 시 `history.clear()` 후 `paint/repaint`

## 3. Version 02 개선 내용

`Version 02`는 동일 구조를 유지하면서 안정성과 검증 가능성을 강화했다.

- `null`/자기 자신 append 방어 추가
- 캔버스 범위 검증(0 <= x < width, 0 <= y < height)
- `Command_DrawSnapshot` 도입으로 렌더 결과를 값 객체로 확인 가능
- `Undo()` 성공 여부를 `bool`로 반환

## 4. 테스트 반영

### 4.1 기본 로직 테스트

- Ver1: `DrawCommand` 실행 검증
- Ver1: `Undo` 이후 `Paint()` 재실행 결과 검증
- Ver2: `Append(null)`, 자기 자신 append, 범위 초과 좌표 예외 검증

### 4.2 Scenario Unit Test

입력 시퀀스를 실제 실행 흐름대로 재현한다.

- 드래그 `(10,10) -> (20,20) -> (30,30)`
- clear 버튼 클릭
- 드래그 `(40,40) -> (50,50)`

검증 포인트:
- clear 이후 이력이 비워지는지
- replay 결과 순서가 입력 순서와 일치하는지
- clear 이후 신규 입력만 남는지

## 6. C# 문법 설명
### 6.1 명령 계약(`interface`)과 이력 컬렉션
- 대상 코드: `Command_Command`, `Command_MacroCommand`
- 선언 의미: 실행 요청을 인터페이스로 통일하고, 컬렉션(`List<Command_Command>`)으로 명령 이력을 관리한다.
- 실행 시 동작: `Append`된 순서대로 `Execute`/`Paint` 재실행이 가능하다.
- 주의점/오해하기 쉬운 차이: 자기 자신 명령을 append하면 무한 재귀 흐름이 생길 수 있어 방어가 필요하다.

### 6.2 스냅샷 값 객체와 경계값 검증
- 대상 코드: `Command_DrawSnapshot`, `Command_DrawCanvas`의 좌표/크기 검증
- 선언 의미: 렌더링 결과를 값 객체로 분리해 상태를 직접 검증하고, 입력 경계 위반을 예외로 명시한다.
- 실행 시 동작: 잘못된 좌표/크기는 즉시 `ArgumentOutOfRangeException`으로 실패한다.
- 주의점/오해하기 쉬운 차이: UI 이벤트 흐름에서 예외를 삼키면 이력/화면 상태가 불일치할 수 있다.
