# Strategy 패턴 정리

## 1. 패턴 개요

Strategy 패턴은 동일한 목적의 알고리즘을 독립 클래스로 분리하고,
실행 시점에 필요한 알고리즘을 선택하거나 교체해 사용하는 행위 패턴이다.

적용 목적:
- 조건문 중심 분기 제거
- 알고리즘 교체 유연성 확보
- 변경 영향 범위 축소

## 2. 예제 도메인

예제는 콜센터 배분 정책 선택 구조다.

- 공통 전략 인터페이스: `Strategy_Scheduler`
  - `Name`
  - `GetNextCall()`
  - `SendCallToAgent()`
- 구체 전략:
  - `Strategy_RoundRobin`
  - `Strategy_LeastJob`
  - `Strategy_PriorityAllocation`
  - `Strategy_AgentGetCall`

버전 구성:
- `Ver1`: 문자열 키 기반 분기
- `Ver2`: 생성자 주입 기반 전략 사용
- `Ver3`: 런타임 전략 교체 + 구조화 결과 반환

## 3. 버전별 구현

### 3.1 Ver1 - 문자열 분기

- 컨텍스트 내부 `switch`로 전략 생성
- 빠른 학습에는 유리하지만 분기 확장 비용이 큼

### 3.2 Ver2 - 생성자 주입

- 컨텍스트가 전략 구현을 직접 생성하지 않음
- 주입된 전략만 실행해 결합도 완화

### 3.3 Ver3 - 전략 교체 + 결과 객체

- `SetScheduler()`로 런타임 교체 지원
- `Run()`이 `Strategy_ScheduleResult_Ver3`를 반환해 검증 가능성 향상

## 4. 버전 비교

| 항목 | Ver1 | Ver2 | Ver3 |
|---|---|---|---|
| 전략 선택 위치 | 컨텍스트 내부 `switch` | 외부에서 생성 후 주입 | 외부 주입 + 런타임 교체 |
| 컨텍스트 수정 필요성 | 높음 | 낮음 | 매우 낮음 |
| 전략 교체 시점 | 실행 전 문자열 분기 | 객체 생성 시 | 실행 중 교체 가능 |
| 반환 형태 | `string` | `string` | `Strategy_ScheduleResult_Ver3` |
| 실무 확장성 | 낮음 | 중간 | 높음 |

## 6. C# 문법 설명
### 6.1 전략 주입과 런타임 교체
- 대상 코드: `Strategy_CallCenterScheduler_Ver2/Ver3` 생성자 주입, `SetScheduler()`
- 선언 의미: 컨텍스트가 구체 전략 생성 책임을 갖지 않고 인터페이스 계약만 의존하도록 분리한다.
- 실행 시 동작: 실행 중에도 전략 인스턴스를 교체해 동일 컨텍스트에서 다른 정책을 적용할 수 있다.
- 주의점/오해하기 쉬운 차이: 주입 객체 null 방어가 없으면 교체 시점에 런타임 예외가 발생한다.

### 6.2 분기식 선택(`switch`)에서 주입식 선택으로 전환
- 대상 코드: Ver1 `switch` 분기, Ver2 이후 인터페이스 주입
- 선언 의미: 알고리즘 선택 로직을 조건문에서 외부 조합(Composition Root)으로 이동한다.
- 실행 시 동작: 신규 전략 추가 시 컨텍스트 수정 없이 전략 클래스와 조합 코드만 추가하면 된다.
- 주의점/오해하기 쉬운 차이: Ver1 구조에서 `switch`만 늘리면 OCP 위반과 회귀 위험이 커진다.
