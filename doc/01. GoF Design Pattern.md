### 5 생성 패턴(Creational)[^1]
- **생**: 생성 패턴 분류명[^1]
- **빌**: Builder(빌더)[^2]
- **프**: Prototype(프로토타입)[^3]
- **팩**: Factory Method(팩토리 메서드)[^4]
- **앱**: Abstract Factory(추상 팩토리)[^5]
- **싱**: Singleton(싱글톤)[^6]

### 7 구조 패턴(Structural)[^7]
- **구**: 구조 패턴 분류명[^7]
- **브**: Bridge(브리지)[^8]
- **데**: Decorator(데코레이터)[^9]
- **퍼**: Facade(퍼사드)[^10]
- **플**: Flyweight(플라이웨이트)[^11]
- **프**: Proxy(프록시)[^12]
- **컴**: Composite(컴포지트)[^13]
- **어**: Adapter(어댑터)[^14]

### 11 행위 패턴(Behavioral)[^15]
- **행**: 행위 패턴 분류명[^15]
- **인**: Interpreter(인터프리터)[^16]
- **이**: Iterator(이터레이터)[^17]
- **체**: Chain of Responsibility(책임 연쇄/책임 사슬)[^18]
- **템**: Template Method(템플릿 메서드)[^19]
- **옵**: Observer(옵저버)[^20]
- **미**: Mediator(미디에이터)[^21]
- **스**: State(상태)[^22]
- **커**: Command(커맨드)[^23]
- **스**: Strategy(전략)[^24]
- **비**: Visitor(비지터)[^25]
- **메**: Memento(메멘토)[^26]

## Footnotes
[^1]: **Creational Patterns**
	객체 “생성” 책임을 캡슐화/추상화하여, 생성 방식 변화가 사용 코드에 미치는 영향을 줄이는 패턴 묶음.
	- **Scope**: 인스턴스 생성 로직 분리, 제품군/버전별 생성 일관성 확보

[^2]: **Builder Pattern**
	복잡한 객체를 단계적으로 조립하고, 다양한 옵션 조합을 안전하게 구성하는 패턴.
	- **Scope**: 옵션 많은 프로토콜 스택/파이프라인 생성, 생성자 파라미터 폭발 방지

[^3]: **Prototype Pattern**
	기존 객체를 복제(clone)하여 새 객체를 생성하는 패턴.
	- **Scope**: 생성 비용이 크거나, 런타임에 템플릿 인스턴스를 복제해 확장해야 할 때

[^4]: **Factory Method Pattern**
	객체 생성을 서브클래스/구현체에 위임하여, 구체 타입 결정을 분리하는 패턴.
	- **Scope**: 버전/환경별 구현 선택, 생성 분기(switch/if) 축소

[^5]: **Abstract Factory Pattern**
	서로 연관된 객체들의 “제품군”을 일관되게 생성하는 인터페이스를 제공하는 패턴.
	- **Scope**: 프로토콜 v1/v2처럼 Parser/Codec/Dispatcher 세트를 함께 교체

[^6]: **Singleton Pattern**
	특정 클래스의 인스턴스를 1개로 제한하고 전역 접근점을 제공하는 패턴.
	- **Scope**: 공용 설정/레지스트리 등 단일 인스턴스가 의미가 있을 때(과도한 전역화 주의)

[^7]: **Structural Patterns**
	클래스/객체를 조합해 더 큰 구조를 만들고, 결합도를 낮추는 패턴 묶음.
	- **Scope**: 계층 분리, 래핑, 합성, 외부 의존 경계 고립

[^8]: **Bridge Pattern**
	추상(Abstraction)과 구현(Implementation)을 분리하여 독립적으로 확장 가능하게 하는 패턴.
	- **Scope**: 전송계층(예: TCP/WS)과 프로토콜 처리 계층을 독립 확장

[^9]: **Decorator Pattern**
	객체를 감싸 기능을 동적으로 추가/조합하는 패턴(상속 대신 합성).
	- **Scope**: 로깅/메트릭/암호화/압축 같은 부가기능을 on/off, 조립

[^10]: **Facade Pattern**
	복잡한 하위 시스템을 단순한 통합 인터페이스로 감싸 사용하는 측을 단순화하는 패턴.
	- **Scope**: 외부에는 `ProtocolClient.send()` 같은 단순 API 제공

[^11]: **Flyweight Pattern**
	공유 가능한 상태를 재사용해 메모리 사용을 줄이는 패턴.
	- **Scope**: 동일한 규격/토큰/정적 메타데이터를 대량으로 다룰 때

[^12]: **Proxy Pattern**
	대리 객체를 두어 접근 제어/지연 로딩/원격 호출/캐싱 등을 수행하는 패턴.
	- **Scope**: 네트워크 호출 래핑, 접근 통제, 캐시/리트라이 정책 부여

[^13]: **Composite Pattern**
	부분-전체 트리를 동일한 인터페이스로 다루는 패턴.
	- **Scope**: 메시지/필드가 계층 구조일 때, 단일/복합을 동일 취급

[^14]: **Adapter Pattern**
	호환되지 않는 인터페이스를 변환해 기존 코드를 수정 없이 재사용하도록 하는 패턴.
	- **Scope**: 서드파티 코덱/네트워크 프레임워크를 내부 인터페이스로 변환

[^15]: **Behavioral Patterns**
	객체 간 상호작용과 책임 분배(알고리즘, 흐름, 통신)를 구조화하는 패턴 묶음.
	- **Scope**: 메시지 처리 디스패치, 상태 전이, 파이프라인, 이벤트 통지

[^16]: **Interpreter Pattern**
	언어/규칙의 문법을 클래스 구조로 표현하고 해석기를 구현하는 패턴.
	- **Scope**: 간단한 DSL/규칙 기반 메시지 필터/쿼리 해석

[^17]: **Iterator Pattern**
	컬렉션 내부 표현을 노출하지 않고 순회 방법을 제공하는 패턴.
	- **Scope**: 메시지/필드/핸들러 목록 순회를 일관되게 제공

[^18]: **Chain of Responsibility Pattern**
	요청을 체인으로 전달하며 적절한 처리자가 처리하도록 하는 패턴.
	- **Scope**: 디코딩→검증→인증→라우팅 등 수신 파이프라인 구성

[^19]: **Template Method Pattern**
	알고리즘 골격은 상위에서 고정하고 일부 단계만 하위에서 재정의하는 패턴.
	- **Scope**: 공통 처리 흐름(에러/계측 포함)을 강제하여 누락 방지

[^20]: **Observer Pattern**
	한 객체의 상태 변화가 다수 객체에게 자동 통지되도록 하는 패턴.
	- **Scope**: 연결 상태 변화, 메시지 수신 이벤트를 구독자에게 방송

[^21]: **Mediator Pattern**
	객체 간 직접 참조를 줄이고 중재자에게 상호작용을 위임하는 패턴.
	- **Scope**: 세션/라우터/디스패처가 컴포넌트 협력을 조율

[^22]: **State Pattern**
	상태에 따라 행위가 달라질 때 상태별 동작/전이를 상태 객체로 분리하는 패턴.
	- **Scope**: 핸드셰이크/인증/READY 등 프로토콜 단계 관리

[^23]: **Command Pattern**
	요청을 객체로 캡슐화해 큐잉/로깅/재시도/권한검사 등을 쉽게 하는 패턴.
	- **Scope**: 메시지 타입별 핸들러를 객체로 분리, 디스패치 테이블화

[^24]: **Strategy Pattern**
	동일 역할의 알고리즘/정책을 교체 가능하게 하는 패턴.
	- **Scope**: 코덱/압축/암호화/프레이밍 정책을 런타임 구성으로 교체

[^25]: **Visitor Pattern**
	객체 구조를 변경하지 않고 새 연산을 추가하는 패턴.
	- **Scope**: 메시지 AST/필드 트리에 대해 검증/직렬화/프린트 등 기능 추가

[^26]: **Memento Pattern**
	객체의 내부 상태를 캡슐화한 채 저장/복원(undo/rollback)하는 패턴.
	- **Scope**: 세션/프로토콜 상태 스냅샷 저장, 실패 시 롤백
