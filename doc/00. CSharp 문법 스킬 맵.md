# C# 문법 스킬 맵

## 1. 목적
`doc/`의 패턴 문서와 해당 `src/` 구현을 교차 검토해, 저장소에서 반복 사용하는 C# 문법 스킬을 재사용 가능한 형태로 정리한다.

## 2. 검토 범위
- Creational: Singleton, AbstractFactory, FactoryMethod, Builder
- Structural: Adapter
- Behavioral: Strategy, TemplateMethod, State, ChainOfResponsibility, Command
- 테스트 검증: `src/unitTest/` 패턴별 테스트

## 3. 핵심 문법 스킬
### 3.1 추상화 계층 (`abstract class`, `interface`)
- 목적: 공통 계약 고정 + 구현 교체 가능성 확보
- 예시:
  - `src/01. Creational Pattern/FactoryMethod/Version 02/FactoryMethod_CarFactory.cs`
  - `src/01. Creational Pattern/AbstractFactory/Version 03/04. Factory/AbstractFactory_DAO_Factory.cs`
  - `src/03. Behavioral Pattern/TemplateMethod/Version 03/TemplateMethod_PlayerLevel.cs`
  - `src/02. Structural Pattern/Adapter/Version 03/02. Target/Adapter_IPrint_Ver2.cs`

### 3.2 다형성 확장 (`virtual`/`override`)
- 목적: 상위 기본 동작 + 하위 선택적 재정의
- 예시:
  - `src/01. Creational Pattern/Builder/Version 03/effecivejava/Builder_Pizza_Ver3.cs` (`virtual SauceInside`, `abstract Build`)
  - `src/03. Behavioral Pattern/TemplateMethod/Version 03/TemplateMethod_PlayerLevel.cs` (`CanJump`, `CanTurn` hook)
  - `src/03. Behavioral Pattern/State/Version 02/State_AdvancedLevel.cs`

### 3.3 중첩 타입 숨김 (`new class`) vs 인스턴스 생성 (`new T()`)
- 목적: 같은 이름의 중첩 Builder 타입을 하위에서 명시적으로 재정의
- 예시:
  - `src/01. Creational Pattern/Builder/Version 01/effecivejava/Builder_NyPizza_Ver1.cs`
  - `src/01. Creational Pattern/Builder/Version 01/effecivejava/Builder_Calzone_Ver1.cs`
- 구분:
  - `public new class Builder ...`: 타입 이름 숨김(hiding)
  - `new Builder_NyPizza_Ver1(this)`: 객체 생성

### 3.4 불변성/읽기 전용 노출 (`readonly`, `IReadOnlyList`, `IReadOnlyCollection`)
- 목적: 내부 상태 변경 차단, 스냅샷 반환
- 예시:
  - `src/01. Creational Pattern/Builder/Version 02/effecivejava/Builder_Pizza_Ver2.cs`
  - `src/01. Creational Pattern/Builder/Version 03/effecivejava/Builder_Pizza_Ver3.cs`
  - `src/03. Behavioral Pattern/Command/Version 02/Command_DrawSnapshot.cs`
  - `src/03. Behavioral Pattern/ChainOfResponsibility/Version 03/ChainOfResponsibility_Result.cs`

### 3.5 생성 제어 (`private constructor`, `sealed`, `static`)
- 목적: 인스턴스 생성 통제, 싱글턴 안전성 강화
- 예시:
  - `src/01. Creational Pattern/Singleton/Version 01/Singleton_ConnectionPool_Ver1.cs`
  - `src/01. Creational Pattern/Singleton/Version 02/Singleton_ConnectionPool_Ver2.cs` (`lock`)
  - `src/01. Creational Pattern/Singleton/Version 03/Singleton_ConnectionPool_Ver3.cs` (`Lazy<T>`, `sealed`)
  - `src/03. Behavioral Pattern/ChainOfResponsibility/Version 03/ChainOfResponsibility_SupportFactory.cs` (`static factory`)

### 3.6 입력 검증/예외 패턴 (`throw`, `nameof`, `?? throw`)
- 목적: 경계값/널 입력 조기 차단
- 예시:
  - `src/01. Creational Pattern/AbstractFactory/Version 03/04. Factory/AbstractFactory_DAO_Factory.cs`
  - `src/01. Creational Pattern/Builder/Version 02/effecivejava/Builder_NyPizza_Ver2.cs`
  - `src/03. Behavioral Pattern/Command/Version 02/Command_DrawCanvas.cs`
  - `src/03. Behavioral Pattern/ChainOfResponsibility/Version 03/ChainOfResponsibility_DelegateSupport.cs`

### 3.7 컬렉션 + 제네릭 + 팩토리 맵 (`Dictionary`, `HashSet`, `Func<T>`)
- 목적: 분기문 축소, 등록 기반 생성/선택
- 예시:
  - `src/01. Creational Pattern/FactoryMethod/Version 02/FactoryMethod_HDI_CarFactory.cs` (`Dictionary<string, Func<FactoryMethod_Car>>`)
  - `src/01. Creational Pattern/Builder/Version 03/effecivejava/Builder_Pizza_Ver3.cs` (`HashSet`, `List`)
  - `src/03. Behavioral Pattern/ChainOfResponsibility/Version 03/ChainOfResponsibility_SupportFactory.cs` (`Func<..., bool>`)

### 3.8 분기 표준화 (`switch`, 정규화 문자열)
- 목적: 입력 키를 안정적으로 표준화해 분기
- 예시:
  - `src/01. Creational Pattern/AbstractFactory/Version 02/04. Factory/AbstractFactory_DAO_Factory.cs` (`Trim().ToLowerInvariant()`)
  - `src/03. Behavioral Pattern/Strategy/Version 01/03. Context/Strategy_CallCenterScheduler_Ver1.cs` (`switch`)
  - `src/01. Creational Pattern/FactoryMethod/Version 02/FactoryMethod_HDI_CarFactory.cs` (`StringComparer.OrdinalIgnoreCase`)

### 3.9 표현식 본문 멤버 (`=>`)와 단순 프로퍼티 캡슐화
- 목적: 읽기 전용 접근자/간결한 반환 표현
- 예시:
  - `src/01. Creational Pattern/FactoryMethod/Version 02/FactoryMethod_Car.cs`
  - `src/03. Behavioral Pattern/Strategy/Version 03/03. Context/Strategy_CallCenterScheduler_Ver3.cs`
  - `src/01. Creational Pattern/AbstractFactory/Version 02/01. Domain/FactoryAbstract_UserInfo.cs`

### 3.10 시나리오 검증 관점의 캐스팅/형 확인 (`as`, `Assert.IsInstanceOfType`)
- 목적: 추상 반환 타입의 실제 구현체/상태 검증
- 예시:
  - `src/unitTest/01. Creational Pattern/01. Creational Pattern - Builder.cs`
  - `src/unitTest/03. Behavioral Pattern/03. Behavioral Pattern - State.cs`

## 4. 문서화 규칙 (메모리 보강)
- 패턴 문서 하단에 `C# 문법 설명` 섹션을 유지한다.
- 작성 순서는 반드시 `대상 코드` -> `선언 의미` -> `실행 시 동작` -> `주의점/오해하기 쉬운 차이`를 따른다.
- 신규 패턴/버전 추가 시 본 문서(스킬 맵)에도 재사용 가능한 문법 포인트를 누적 반영한다.

## 5. 패턴별 적용 체크
- Singleton: `private constructor`, `static`, `sealed`, `Lazy<T>`, `lock`
- AbstractFactory: `abstract factory`, `interface`, `switch`, `nameof`, 예외 계약
- FactoryMethod: `Dictionary<string, Func<T>>`, `StringComparer.OrdinalIgnoreCase`, 입력 검증
- Builder: 중첩 타입 `new` 숨김, `IReadOnly*` 스냅샷, `virtual/override` 체인
- Adapter: 상속(Class Adapter) vs 합성(Object Adapter), `?? throw`
- Strategy: 인터페이스 기반 주입, 런타임 교체, 결과 객체(`sealed`)
- TemplateMethod: `abstract` 골격 + `virtual` hook
- State: 상태 객체 교체, 구조화 결과 반환(`sealed`)
- ChainOfResponsibility: 체인 연결 + `Func<T, bool>` delegate 주입
- Command: 명령 인터페이스, 이력 컬렉션, 스냅샷 값 객체
