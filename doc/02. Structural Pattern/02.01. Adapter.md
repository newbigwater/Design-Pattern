# Adapter 패턴 정리

## 1. 패턴 개요

Adapter 패턴은 기존 클래스(Adaptee)의 인터페이스를
클라이언트가 기대하는 인터페이스(Target)로 변환해 재사용 가능하게 만드는 구조 패턴이다.

적용 목적:
- 기존 코드 재사용
- 인터페이스 불일치 해소
- 클라이언트 코드 변경 최소화

## 2. 예제 도메인

예제는 문자열 출력 형식을 변환하는 구조다.

- Adaptee: `Adapter_Banner`
  - `ShowWithParen()`
  - `ShowWithAster()`

버전 구성:
- `Ver1`: 추상 클래스 Target 기반
- `Ver2`: 상속 기반 Class Adapter
- `Ver3`: 합성 기반 Object Adapter

## 3. 버전별 구현

### 3.1 Ver1 - 추상 Target 기반

- 기존 추상 Target(`Adapter_Print_Ver1`) 계약을 유지
- 내부에서 `Adapter_Banner`를 위임 호출

### 3.2 Ver2 - Class Adapter (상속)

- Adapter가 `Adapter_Banner`를 상속
- 동시에 Target 인터페이스(`Adapter_IPrint_Ver2`) 구현
- 간결하지만 상속 제약 존재

### 3.3 Ver3 - Object Adapter (합성)

- Adapter가 `Adapter_Banner` 인스턴스를 주입받아 사용
- 결합도를 낮추고 테스트/확장에 유리
- `null` 주입 방어 포함

## 4. 버전 비교

| 항목 | Ver1 | Ver2 | Ver3 |
|---|---|---|---|
| Target 형태 | 추상 클래스 | 인터페이스 | 인터페이스 |
| 적용 방식 | 위임(기존 구조 호환) | 상속 | 합성 |
| 결합도 | 중간 | 높음(기반 클래스 의존) | 낮음(구성 기반) |
| 확장성 | 중간 | 중간 | 높음 |
| 실무 권장도 | 중간 | 제한적 | 높음 |

## 6. C# 문법 설명
### 6.1 상속 기반 Adapter와 합성 기반 Adapter
- 대상 코드: Ver2 Class Adapter, Ver3 Object Adapter
- 선언 의미: 상속은 구현 간결성을, 합성은 결합도 완화를 제공한다.
- 실행 시 동작: Ver2는 기반 클래스 API를 직접 확장하고, Ver3는 주입받은 `Adapter_Banner`에 위임 호출한다.
- 주의점/오해하기 쉬운 차이: C#은 단일 상속이므로 Class Adapter는 확장 제약이 크고, 실무에서는 Object Adapter가 더 유연하다.

### 6.2 생성자 널 방어 (`?? throw`)
- 대상 코드: Ver3 Adapter 생성자
- 선언 의미: 의존 객체 주입 시점에 null을 즉시 차단해 런타임 지연 오류를 방지한다.
- 실행 시 동작: 잘못된 주입은 생성 단계에서 `ArgumentNullException`으로 실패한다.
- 주의점/오해하기 쉬운 차이: 메서드 내부에서 늦게 null 검사하면 실패 지점 추적이 어려워진다.
