# Singleton 패턴 정리

## 1. 패턴 개요

Singleton 패턴은 애플리케이션 전체에서 특정 클래스의 인스턴스를 하나만 생성하고,
모든 사용 지점에서 동일 인스턴스에 접근하도록 만드는 생성 패턴이다.

핵심 목표:
- 인스턴스 유일성 보장
- 전역 접근 지점 제공

## 2. 예제 도메인

예제는 `ConnectionPool` 성격의 클래스를 가정한다.
동일한 연결 관리 객체를 여러 호출 지점에서 공유해야 하므로 Singleton에 적합하다.

버전 구성:
- `Singleton_ConnectionPool_Ver1`: Eager Initialization
- `Singleton_ConnectionPool_Ver2`: Double-Checked Locking
- `Singleton_ConnectionPool_Ver3`: `Lazy<T>` 기반 개선

## 3. 버전별 구현

### 3.1 Ver1 - 즉시 초기화

- 타입 로드 시 인스턴스를 즉시 생성
- 구현은 단순하지만, 사용하지 않아도 생성 비용이 발생

### 3.2 Ver2 - Double-Checked Locking

- 최초 접근 시 지연 생성
- 멀티스레드 상황에서 `lock`으로 경쟁 조건 방지
- 구현 복잡도는 증가

### 3.3 Ver3 - `Lazy<T>` 기반

- 지연 생성 + 스레드 안전을 프레임워크에 위임
- 구현 복잡도를 낮추면서 안정성 확보
- `CreatedAt`, `GetConnection()` 같은 부가 상태/동작 관리 용이

## 4. 버전 비교

| 항목 | Ver1 | Ver2 | Ver3 |
|---|---|---|---|
| 생성 시점 | 타입 로드 시 즉시 | 최초 접근 시 지연 생성 | 최초 접근 시 지연 생성 |
| 스레드 안전 처리 | 정적 초기화에 의존 | `lock` 직접 구현 | `Lazy<T>`에 위임 |
| 구현 복잡도 | 낮음 | 높음 | 낮음 |
| 제어 유연성 | 낮음 | 높음 | 중간 |
| 실무 권장도 | 제한적 | 상황 의존 | 높음 |
